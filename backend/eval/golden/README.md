# Golden set: розмітка силабусів

Golden set — це 15–30 анонімізованих силабусів KSE, розмічених академічним директором. За ним скрипт оцінки (`npm run eval`) рахує precision/recall по кожному критерію рубрики (`backend/services/ai/rubric/criteria.js`), частку дублікатів і валідність доказів.

## Що розмічати

Для кожного силабусу — один файл `<назва>.annotation.json` за схемою `annotation.schema.json`. Приклад: `example.annotation.json`.

- `file` — ім'я анонімізованого файлу силабусу (самі силабуси лежать окремо, не в git, якщо містять персональні дані);
- `criteria` — вердикт по **кожному** критерію з рубрики (34 записи), без пропусків:
  - `ok` — критерій виконано;
  - `issue` — є проблема. Тоді обов'язкові `severity` (`critical`/`high`/`medium`/`low`) і `evidence` — заголовки або цитати до 15 слів, де видно проблему (або `"document-level"`, якщо чогось немає взагалі). Якщо файл уже розбито на блоки, можна вказати `evidenceBlockIds`;
  - `not_applicable` — критерій не стосується курсу;
- `acceptableFix` — необов'язково: що саме було б прийнятною правкою (1–2 речення). Не потрібно писати готовий текст.
- `notes` — будь-які коментарі.

## Правила розмітки

1. Розмічайте тільки за текстом силабусу. Що в голові викладача — не рахується.
2. Якщо розділ є під іншою назвою, це `ok`.
3. `severity` — ваша думка, а не значення за замовчуванням. Якщо вона відрізняється від рубрики, це корисний сигнал.
4. Серед силабусів має бути **4–6 «чистих»**: без жодного `issue` або з 1–2 дрібними (`low`). Вони потрібні, щоб міряти хибні спрацювання.
5. Підберіть різні типи: короткі й довгі, з кейсами й без, з AI-політикою й без, різні програми (MBA, EMBA тощо).
6. Анонімізуйте: приберіть імена викладачів, контакти, посилання на особисті ресурси.

## Як перевіряти розмітку

Після розмітки можна провалідувати файл за схемою, наприклад: `npx ajv-cli validate -s annotation.schema.json -d "*.annotation.json"`.
